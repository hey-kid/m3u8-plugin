# M3U8 捕手

基于 **TypeScript + HTML/CSS + Vite + Manifest V3** 的 Edge 浏览器扩展。自动监听 m3u8 请求，将 HTTP 2xx 正常地址与异常地址分开显示；保留当前网页列表，并把所有普通窗口中抓到的地址归档到本机 IndexedDB。支持搜索、复制、手动删除和导出全部历史备份，不自动删除历史记录。

## 安装到 Edge

1. 在项目目录执行 `npm install`、`npm run build`，或直接使用随附的 `dist` 构建目录。
2. 在 Edge 地址栏打开 `edge://extensions/`。
3. 启用“开发人员模式”，点击“加载解压缩的扩展”。
4. 选择本项目的 **`dist` 文件夹**，不是项目根目录。
5. 建议在工具栏固定“M3U8 捕手”图标，打开或刷新目标视频网页，播放视频后点击图标查看结果。

若使用 ZIP，请先解压，选择解压后直接包含 `manifest.json` 的文件夹。扩展需要允许访问目标网页和视频资源所在域名；如限制为点击时访问，将无法在打开网页时自动监听。更新代码并重新构建后，请在扩展管理页重新加载扩展，再刷新目标网页。

### 升级到 0.3.2

使用 0.3.2 的构建文件覆盖原来加载的 `dist` 目录，然后在 `edge://extensions/` 中重新加载现有的“M3U8 捕手”。保持相同目录和扩展身份，不要卸载重装，以保留已存历史。从 0.2.0 升级不新增权限、不更改数据库版本，原记录会按已保存的状态直接分类；没有状态的旧记录进入“待确认”。如从 0.1.0 升级，Edge 可能提示新增的本地存储权限，允许后继续使用。

0.3.2 将成功范围从仅 HTTP 200 修正为所有 HTTP 2xx（200–299），包括范围请求的 206。已有历史中的 206 记录会按新规则直接归入正常，无需重新抓取。分类按钮只显示“正常 / 异常 / 待确认 / 全部”，右侧独立徽标表示地址数量，HTTP 判定规则放在下方说明和正常按钮的悬停提示中。

升级后新捕获的地址会自动长期保存。旧版本中已经因刷新、关闭标签页或重启而消失的记录无法恢复。

## 当前网页与全部历史

- 按请求 URL 的 `.m3u8` 路径后缀识别资源，支持带查询参数和签名的地址。
- 按 HLS 响应 `Content-Type` 补充识别没有 `.m3u8` 后缀的接口。
- **当前网页**：每个标签页分别收集，包括嵌入播放器；导航后重置临时列表，避免不同网页串在一起。
- **全部历史**：所有网站的地址统一持久保存，刷新、关闭标签页和正常重启 Edge 后仍能查看。在浏览器内部页或新标签页也能打开历史。
- 当前网页和历史都提供“正常 / 异常 / 待确认 / 全部”筛选，默认显示正常地址。每个按钮右侧的徽标表示地址数量。异常仅是分类，不会被自动删除。
- 同一完整 URL 合并显示，更新捕获次数和响应状态；不同签名参数保留为不同地址。
- 历史保存首次/最近捕获时间、累计次数、完整地址、资源域名及最近的来源网页地址/标题；同一 URL 多次出现时聚合为一条。
- 历史搜索支持完整地址、资源域名、来源网页地址和标题，不区分大小写；按最近捕获排序，每页显示 30 条。
- 单条复制保留完整地址；底部复制操作只包含当前选择的类别。历史复制同时应用搜索条件，包含全部匹配分页，每行一条。
- 单条历史可手动删除，操作前有确认。删除不影响当前网页临时列表；同一请求后续到来的响应不会把它恢复，真正再次请求时会重新保存。
- **导出备份**：生成包含全部历史的 JSON 文件，不受搜索条件或当前分页影响。格式包括 `format`、`version`、`exportedAt`、`count` 和完整 `items`，可留存、查看或交给其他工具处理；本版本未提供导入按钮。
- 工具栏角标显示资源数量，弹窗打开时列表实时更新。
- 长地址支持展开查看和手动选择复制；加载、空列表、异常和内部页面均有对应提示。

## 正常与异常分类

| 列表 | 规则 |
| --- | --- |
| 正常 | 已观测到 HTTP 2xx（200–299），且没有网络错误；包括 200、201、204、206 等 |
| 异常 | 其他有效 HTTP 状态码，或网络失败；包括 300、302、304、403、404、500 等 |
| 待确认 | 还没有收到有效状态码，也没有网络错误；旧记录缺少状态时也归入这里 |
| 全部 | 显示以上所有类别 |

分类依据网页实际发出的请求，不会为筛选额外访问视频地址。同一完整 URL 多次请求时，按最近捕获到的结果更新类别；例如 404 后重新请求返回 200 或 206，会移入正常。2xx 响应头后发生断流仍属异常，后续真正观测到新的成功结果才恢复正常。重叠请求按结果到达的时间排序，而不是按请求开始时间排序。

206 表示服务器成功返回范围请求指定的部分内容，是正常的 HTTP 成功响应。这里的“正常”仅表示请求状态成功，不校验播放列表正文或后续分片；例如 204 是成功响应，但没有响应正文，不能据此保证是可用的播放列表。HTTP 语义参见 [RFC 9110：成功 2xx](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3) 和 [206 Partial Content](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7)。

历史的类别计数统计当前关键词在全库中匹配的记录，分页只显示选定类别。点击“复制全部正常/异常/待确认”包含该类别的所有匹配页。导出备份始终包含整个历史库，包括异常和待确认，不受类别或关键词影响。

## 使用边界

- “自动”指自动监听之后发生的请求，不会还原安装前或重新加载扩展前已完成的请求。已有网页请刷新或重新播放。
- 页面必须实际发出 m3u8 请求；有的网站需要点击播放后才会请求。
- Edge 内部页、扩展页、PDF、受限商店页面或使用其他视频协议的网页，可能无法捕获。地址不含后缀且服务器也没有返回 HLS 类型的资源，不在第一版识别范围内。
- 同一单页应用内部切换视频时，临时发现的地址会继续留在当前页；完整页面导航或刷新后重置临时列表，持久历史仍保留。
- 保存的是播放列表地址，不包含视频文件。已捕获或 HTTP 2xx 不代表链接在其他工具中一定可播放，地址可能过期或依赖原网页的访问上下文。
- 当前网页临时列表最多保留 300 条不同地址，到达上限后界面会提示。持久历史没有条数淘汰规则，第 301 条及以后的新地址仍会归档。
- 如果用户允许扩展在隐私窗口运行，隐私窗口的请求只进入当前页临时列表，不写入普通窗口的持久历史。

## 本地数据与权限

当前网页结果使用 `chrome.storage.session`，在后台休眠期间保留，页面导航、关闭标签页、浏览器重启或扩展重新加载时可清除。

全部历史使用扩展自身的 **IndexedDB**（数据库 `m3u8-catcher-history`，仓库 `playlists`），与临时列表分开。记录保存在当前电脑、当前 Edge 用户配置和当前插件身份中，刷新/关标签/正常浏览器重启/同身份重新加载扩展不会自动删除。换电脑、更换用户配置或卸载重装不能依赖原数据仍在，因此重要记录建议主动导出 JSON 备份。

`unlimitedStorage` 用于避免默认扩展配额和存储回收限制，并不表示物理磁盘无限大。存储不足或写入失败时会显示持续提示；扩展不会通过自动删除旧记录腾空间。失败提示不会因下一次写入成功而自动消失，以免掩盖曾经未保存的地址。可先复制当前页地址，并在存储恢复后重新播放/请求需要保存的资源。

扩展自身不会上传抓取记录、请求视频内容或修改网站请求。仅记录观察到的资源 URL、来源网页地址/标题、资源域名、请求方法、时间、次数和响应状态。完整 URL 可能包含网站签名参数，复制、导出和分享时请留意其用途。

| 权限 | 用途 |
| --- | --- |
| `webRequest` | 观察请求 URL 和 HLS 响应类型 |
| `webNavigation` | 区分顶层页面导航、刷新和历史页面恢复，防止串页 |
| `storage` | 保存临时结果、历史更新通知和存储错误状态 |
| `clipboardWrite` | 点击单条/全部复制时写入剪贴板 |
| `unlimitedStorage` | 允许本机 IndexedDB 历史持续增长，避免默认配额/回收限制 |
| HTTP/HTTPS 主机访问 | 覆盖网页与跨域视频 CDN，支持自动发现 |

## 开发与验证

开发环境支持 Node.js 22.12 起的 22.x、24.x 或 26+，推荐 Node 24。

```powershell
npm install
npm run build
npm test
npm run verify
```

`npm run dev` 为构建监听模式，生成文件仍位于 `dist`，修改后在扩展管理页重新加载。`npm run verify` 顺序运行当前页、持久历史和状态分类三套验收；`npm run verify:history` 和 `npm run verify:status` 可只构建并验收相应功能。脚本使用独立临时浏览器配置和仅监听本机回环地址的测试服务；当前页脚本优先 Edge、必要时尝试已有 Playwright Chromium，其余脚本使用实际 Edge。测试结束后自动关闭浏览器和服务，删除临时配置/下载并恢复原剪贴板文本。截图和 JSON 报告位于 `artifacts/verification`，不包含用户浏览器数据。剪贴板验收应串行运行，避免多个测试同时写入。

项目没有常驻开发服务器。图标源生成脚本为 `scripts/generate-icons.ps1`，已生成的 PNG 随项目保留。

验证脚本使用本地可控的网页和播放列表，在实际 Edge 扩展环境中检查弹窗入口、网络捕获、真实剪贴板、页面导航、下载链接和 BFCache 恢复。历史验收还会在同一个临时浏览器配置中真正关闭并重新启动 Edge，检查记录保留，并验证超过 300 条、分页、搜索、删除与全量 JSON 下载。该验证不代表所有外部视频网站均已实测；外部网站是否能发现资源，仍取决于其播放协议、请求时机与扩展访问权限。

## 代码位置

- `public/manifest.json`：扩展配置和权限。
- `src/background.ts`：请求监听、导航隔离、会话结果、独立历史归档和角标。
- `src/capture.ts`：资源识别和聚合逻辑。
- `src/status.ts`：HTTP 2xx、非 2xx 与网络失败、待确认的统一分类规则。
- `src/history.ts`：IndexedDB 事务、来源记录、搜索分页、删除及 JSON 导出。
- `src/popup.ts`、`src/popup.css`、`popup.html`：弹窗界面与复制交互。
- `scripts/verify-extension.mjs`：真实浏览器验收脚本。
- `scripts/verify-history.mjs`：真实浏览器持久历史和重启验收脚本。
- `scripts/verify-status.mjs`：真实 HTTP 状态、网络失败、分类筛选和复制/备份验收脚本。
